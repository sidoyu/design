## 1. 정체성과 원칙

**흰 바탕 + 검정 잉크 + 네온 그린 포인트.** Geist 타이포그래피, **직각 모서리, 박스 없음** — 구획은 수평선·여백·타이포그래피로(gov.uk 문법). 플랫, 장식 없음. 기능적인 웹.

1. **라이트 전용.** 다크모드는 만들지 않는다. `dark:` 클래스 금지. 시스템 다크모드도 무시한다(`color-scheme: light`) — 카카오 인앱 브라우저 등에서 강제 반전을 막기 위한 의도적 결정.
2. **네온 그린(#28FF35)은 정체성 포인트다.** 허용: 텍스트 링크 밑줄(`brand`) · 호버 틴트와 포커스 링 바깥 테(`brand-hover`) · 표시된 글자 범위(`brand-selection` — 끌어 선택한 글자 `::selection` 과 검색으로 찾은 낱말 `mark`, v0.8.1). 금지: 면 배경·글자 색·**선택된 항목 표시·역할 구분·상태 표시**. 이유는 정체성(한 화면에 액센트 하나)이다 — 잉크 면 위에서 15.45:1 이어도 네온 글자를 쓰지 않는다. 흰 배경 1.36:1 은 글자 금지의 추가 이유다.
3. **시맨틱 토큰 우선.** raw 색·임의 투명도 직접 사용 금지. 토큰에 없는 값이 필요하면 먼저 토큰을 추가한다(이 문서와 함께).
3-1. **모서리는 직각.** 라운딩 전면 금지(`rounded*`·`border-radius` — radius 토큰은 v0.3.0에서 삭제). 그림자·블러·그라데이션도 금지(예외 = 포커스 링 `box-shadow`, 셀렉트 화살표를 그리는 도형 기법 `linear-gradient` — 둘 다 base.css 정본 안에만 있다). 2026-06-11 결정: 둥근 카드가 'AI 생성물' 인상을 줌 — 플랫·샤프로 전환.
3-2. **박스 금지(v0.4.0).** 콘텐츠를 사면 테두리 상자에 담지 않는다. 구획은 **수평선(`border-t/b border-line`)·여백·타이포 위계**로만. 사면 테두리는 다음 셋에만 쓴다(v0.7.0 열거): ① 입력 영역(`.sd-field`·`.sd-composer`, 잉크 2px — "입력하는 곳") ② 떠 있는 층(`.sd-layer`, 잉크 1px — 그림자 대신) ③ 경계 자체가 내용인 것(색 견본·재현물 틀, `line`). 그 밖의 선은 표 머리·몸 경계(잉크 1px)와 행 구분선, 그리고 인셋 좌측 2px 선(`.sd-callout`·`.sd-details`·목록 선택)이며 이것들은 박스가 아니다. 면(`bg-surface-subtle`)은 버튼·배지·인라인 코드 같은 작은 기능 요소에만 — 넓은 콘텐츠 면 금지(표 헤더도 면 없음, v0.6.0). 넓은 면의 예외는 둘이다: 코드 블록(`pre.sd-code` — 코드의 시작과 끝을 보여 준다) · 대화의 사용자 발화(`.sd-user-turn` — §16-8, 2026-10-29 소유자 결정). 2026-06-11 결정: gov.uk식 기능 우선("박스도 장식이다").
4. **색 단독으로 정보를 전달하지 않는다.** 차트·상태 표시는 텍스트·수치 병행. 구분 기능을 맡는 선·면(선택·현재 위치·머리와 몸의 경계·상태)은 잉크 계열(흰 배경 3:1 이상) 또는 상태색으로 그린다. `line`·`surface-subtle` 은 구획 전용이고 뜻을 싣지 않는다(v0.6.0). 예외 = 대화의 사용자 발화 면 — 면 혼자가 아니라 오른쪽 위치와 함께 역할을 알린다(§16-8, v0.7.0).
5. **과토큰화 회피.** 간격은 Tailwind 기본 4px 스케일을 그대로 쓰고, 페이지 표준은 PageShell이 강제한다. 그림자·z-index·애니메이션 토큰은 의도적으로 없다(§13).

## 3. 색 토큰

원본: `tokens/tokens.json` → 발행: `dist/tokens.css`(Tailwind `@theme`) · `dist/tokens.vars.css`(일반 CSS 용 `:root` 변수 — 이름·값이 같다, 색·폭·글꼴) · `dist/base.css`(모양 정본 + 버전 도장). 유틸리티 예: `bg-brand-hover` `text-ink-muted` `border-line`.

대비 = (L밝은 + 0.05) / (L어두운 + 0.05), L = WCAG 2 상대 휘도, 투명 토큰은 흰 배경에 합성해 계산한다.

| 토큰 | 값 | 용도 | 금지 |
|---|---|---|---|
| `brand` | `#28FF35` | 정체성 포인트: 텍스트 링크 밑줄 (호버·포커스 바깥 테·표시된 글자 범위는 아래 두 투명 토큰) | 면·글자·선택된 항목·역할·상태 표시 |
| `brand-hover` | `rgba(40,255,53,.12)` | 인터랙티브 호버 배경 · 포커스 링 바깥 테 | 정적 요소에 사용 |
| `brand-selection` | `rgba(40,255,53,.22)` | 표시된 글자 범위 전용: 끌어 선택(`::selection`) · 검색으로 찾은 낱말(`mark` — v0.8.1, 규칙은 base.css 가 갖는다) | 그 외 전부 |
| `ink` | `#000` | 제목·본문·solid 버튼 배경·선택 표시·입력 테두리 | — |
| `ink-muted` | `rgba(0,0,0,.70)` | 보조 본문·설명·입력 라벨(`.sd-label`)·표 머리 (흰 배경 8.52:1) | — |
| `ink-faint` | `rgba(0,0,0,.55)` | 메타(`.sd-meta`)·eyebrow·날짜·placeholder (흰 배경 4.76:1 — 글자 하한) | **이보다 옅은 텍스트 금지** |
| `surface` | `#FFF` | 페이지 배경(구획 블록은 투명) | — |
| `surface-subtle` | `rgba(0,0,0,.03)` | ghost 버튼·배지·코드 면 · 대화의 사용자 발화 면(v0.7.0) (흰 배경 1.07:1) | 상태·선택을 싣는 것 |
| `line` | `rgba(0,0,0,.10)` | 구획선 전용 (흰 배경 1.25:1 — 입력·떠 있는 층 테두리는 `ink`) | 뜻을 싣는 것 · 임의 투명도 변형 |
| `error` | `#B3261E` | 오류·실패 — 글자·가는 선·작은 표지 (흰 6.54 · `surface-subtle` 위 6.12 · `brand-hover` 위 6.16) | 면 · 차트 |
| `attention` | `#B45309` | 살펴볼 것 있음·판정 불가 — 글자·가는 선·작은 표지 (흰 5.02 · 4.70 · 4.73) | 면 · 차트 |

상태색 두 개는 적록 색약 근사에서 거의 같은 색으로 보인다. 그래서 상태는 색에 기대지 않고 문구(「실패」/「점검 필요」)와 표지 모양(채운 사각/빈 사각)으로 가른다(§16). 성공·정보에는 색을 주지 않는다(§13). `attention` 이라는 이름은 GitHub Primer 에서 빌렸지만, "판정 불가"를 여기에 넣는 것은 sidoyu 자체 결정이다.

마이그레이션 매핑: `black/70·/60→ink-muted`, `black/50·/45·/40→ink-faint`, `black/10·/15·/20(테두리)→line`, `black/[.03]·/5(배경)→surface-subtle`. 더 보조적인 텍스트가 필요하면 색을 더 옅게 하지 말고 **크기·위치·간격**으로 위계를 만든다.

## 4. 타이포그래피

- 폰트: **Geist**(본문·제목), **Geist Mono**(코드·표 숫자, `tabular-nums` 병용).
- 글꼴 스택은 토큰으로 발행한다(v0.7.0): `--font-sans` = `"Geist", "Apple SD Gothic Neo", "Noto Sans KR", ui-sans-serif, system-ui, sans-serif` · `--font-mono` = `"Geist Mono", ui-monospace, "SF Mono", Menlo, monospace`. base.css 가 `body` 에 `--font-sans` 를 건다. 웹폰트 파일을 불러오는 것은 소비처 몫이다(§17). next/font 소비처는 glue 에서 첫 글꼴만 next/font 변수로 바꾸고 한글 폴백은 그대로 둔다(§11).
- 크기는 **6단만 허용**: `text-xs`(12 메타·라벨) · `text-sm`(14 본문 기본) · `text-base`(16 긴 글·입력칸·주 목록 행 제목) · `text-lg`(18 섹션 제목) · `text-2xl`(24 페이지 제목) · `text-3xl`(30 대시보드 KPI 한정).
- 입력칸 글자는 16px 이다(`.sd-field`·복합 입력, v0.7.0) — 아이폰 Safari 는 16px 미만 입력칸에 포커스가 오면 화면을 확대한다.
- **주 목록의 행 제목은 16px 이다**(v0.8.0, `.sd-row-title` = 16/24): 화면의 주 내용이 목록인 곳(대화 목록·검색 결과)에서 행마다 하나뿐인 제목 칸에만 붙인다. 같은 행의 다른 칸(메타·ID·단추)과 보조 목록(사이드바 등)의 행 제목은 14·12 그대로다. 계기 = 표를 가이드 `.sd-table`(14px)로 옮기며 대화 제목이 이관 전 16px 에서 14px 로 작아져 읽기 어려워진 실측(개인 대시보드, 2026-11-02 소유자 결정). 휴대폰 배치도 같은 16/24 이다 — 화면 폭에 따라 6단 밖 값(15px 등)을 만들지 않는다.
- 굵기는 넷뿐이다: 400(본문) · 500(`font-medium` 라벨·버튼 — 이 문서의 "굵게") · 600(`font-semibold` 섹션·카드 제목) · 700(`font-bold` 페이지 제목).
- 소문자 라벨(eyebrow)은 `text-xs tracking-wide uppercase text-ink-faint`.
- 줄간격은 `text-*` 가 주는 값뿐이다(`leading-*` 금지). 긴 글 줄간격(1.75 — Tailwind typography 의 기본값과 같다)은 긴 글 영역(`.prose`·`.sd-prose`)에만 둔다. 대화의 사용자 발화(`.sd-user-turn`)는 짧은 글이라 `text-base` 의 줄간격(24px)을 쓰되, 단위 없는 1.5 로 적는다(v0.8.0 — 고정 길이면 안쪽 제목이 같은 24px 를 물려받아 줄이 겹친다). 예외 = 코드 블록 1.55(여러 줄 코드는 줄 구분이 넓어야 들여쓰기를 따라 읽힌다).
- prose 영역의 제목 크기·굵기는 `prose.css`가 6단 스케일로 정렬한다: h1=2xl/bold · h2=lg/semibold · h3=base/semibold · h4=sm/semibold (§6 prose.css).

## 5. 간격·레이아웃

- **페이지 틀은 PageShell이 유일한 진입점**: 바깥 틀은 항상 **wide(64rem) 중앙 배치**(`mx-auto w-full max-w-wide px-6 pt-6 pb-14`). 모든 페이지의 본문 왼쪽 시작선 = 머리글 맨 앞 요소의 보이는 왼쪽 가장자리(**단일 좌측 기준선**, gov.uk 문법 · 무엇이 보이는 가장자리인지는 §5-1 「머리글 맨 앞 요소」, v0.11.0). 페이지마다 패딩을 손대지 않는다.
- 폭 3종은 **컨테이너 위치가 아니라 줄 길이(measure) 상한**: reading/narrow는 안쪽 콘텐츠 레이어에 왼쪽 정렬로 적용된다(중앙 배치 아님).

| 폭 | 토큰 | 값 | 의미(줄 길이 상한) |
|---|---|---|---|
| `wide` | `max-w-wide` | 64rem(1024px) | 바깥 틀 폭 그대로(상한 미적용) — 카드 그리드·표(홈·플레이그라운드) |
| `reading` | `max-w-reading` | 48rem(768px) | 글·리스트·대시보드의 줄 길이 상한 (기본값) |
| `narrow` | `max-w-narrow` | 28rem(448px) | 폼(CV·연락처)의 줄 길이 상한 |

- 페이지 패딩 `px-6`은 바깥 틀에 있어 measure 밖 — 실측 본문 폭이 토큰 값 그대로다(reading=48rem=768px).
- 간격 표준: 구획 블록(Card) 세로 `py-5`(20px) · 그리드/리스트 간격 `gap-4`(16px) · 섹션 사이 `mt-10`(40px) · 제목 아래 `mt-2`(8px) · 라벨-입력 `gap-2`(8px).
- 인셋 텍스트: 보조 주석 블록은 `.sd-callout`(좌측 2px `line` + `pl-3` — gov.uk inset text 문법, 사면 박스 금지(§1-3-2)의 대체. 변형은 §6).
- 그리드: wide 페이지는 `grid gap-4 sm:grid-cols-2 lg:grid-cols-3`.

### 5-1. 작업 화면 배치 (v0.6.0)

- 문서형 페이지는 PageShell 을 쓴다. 작업 화면(사이드바·고정 입력창이 있는 화면)은 전체 폭을 쓰고, 본문 줄 길이만 `reading` 상한을 지킨다. 새 폭 토큰·AppShell 부품은 만들지 않는다.
- 머리글: 제품명은 왼쪽, 상대 제품으로 가는 링크는 오른쪽 끝에 둔다. 머리글 링크 = `.sd-target .brand-underline`, 2개 이상이면 `.sd-tabs` + 현재 위치에 `aria-current`(v0.7.0). 페이지 이동은 링크로, 값 선택은 Segmented 로 한다(이동을 단추로 만들지 않는다). 머리글 글자 크기·굵기(v0.7.1) = 제품명 700 · 상대 제품 링크 14px·500(개인 작업 화면 두 곳이 맞춘 값).
- 작업 화면의 첫 요소는 건너뛰기 링크다(§6 행동 패턴, v0.7.0). 문서형 페이지는 `<main>` 랜드마크로 충족한다.
- 머리글은 화면 가장자리를 기준으로 놓고, 본문 열(`reading` 상한)의 끝과 맞추지 않는다 — 넓은 화면에서 머리글 오른쪽 끝과 입력창 오른쪽 끝이 다른 것은 규칙대로다. 좁은 화면(48rem 미만)에서는 머리글과 본문이 같은 좌우 여백을 쓴다(v0.6.1).
- **머리글 맨 앞 요소**(v0.11.0): 머리글의 맨 앞 요소(로고 그림·아이콘 단추·제품명 중 맨 앞 것)는 평소 보이는 왼쪽 가장자리를 머리글 왼쪽 여백 선에 둔다. 보이는 가장자리 = 면이 있는 단추는 면 · 면 없는 아이콘 단추(`.sd-btn--plain`, §6 Button)는 아이콘 상자(20px — 아이콘 그림 속 빈 자리는 따지지 않는다) · 로고 그림은 그려진 부분 · 제품명은 첫 글자. 보이는 가장자리를 음수 여백으로 여백 선 밖에 내밀지 않는다(면이 여백 선 밖으로 나가면 왼쪽 시작선이 하나 더 생긴다). 면 없는 아이콘 단추는 투명한 누르는 자리가 아이콘 상자 양옆으로 10px(sm 8px) 더 있어, 아이콘 상자를 여백 선에 맞추면 이 자리가 여백 선 밖으로 나간다 — 이것은 내미는 것이 아니다(소비처가 `margin-inline-start: -0.625rem`, sm `-0.5rem` 로 맞춘다). 이렇게 둘 때 머리글 왼쪽 여백은 `calc(0.625rem + 4px)`(sm `calc(0.5rem + 4px)` — 기본 글자 크기에서 14px·12px) 이상이어야 포커스 링의 잉크 선(단추 바깥 4px)이 화면 가장자리에서 잘리지 않는다 — 더 좁으면 단추 상자를 여백 선에 둔다. 제품명이 맨 앞이 아니면 그 뒤에 온다.
- **좁은 화면의 머리글은 한 줄이다**(v0.11.0): 48rem 미만에서 머리글 안의 부가 정보(모델 이름·연결 상태 설명 같은 줄)를 제품명 아래 둘째 줄로 접지 않는다. 그런 정보는 본문 쪽 메타 줄(대화 머리 등, `.sd-meta`)로 옮기고, 머리글에는 맨 앞 요소 · 제품명 · 짧은 상태 글자 · 오른쪽 끝 링크·단추만 남긴다. 계기 = 개인 에이전트 화면의 좁은 폭 머리글이 두 줄로 접혀 왼쪽 시작선이 넷으로 갈린 실측과 다른 서비스 조사(Material 3 top app bar · Apple HIG Toolbars · AI 채팅 서비스 휴대폰 화면 — 모두 한 줄).
- 좁은 화면 경계는 **48rem 하나**다(이보다 좁으면 사이드바 → 서랍 · 쌓기 변형을 붙인 주 목록 표 → 쌓기, §6 표). base.css 의 화면 폭 쿼리도 이 값 하나이고 범위 문법으로 쓴다(`(width < 48rem)`, v0.11.0 — 옛 `max-width: 47.99rem` 은 47.99rem 과 48rem 사이 소수 폭에서 좁은 규칙도 넓은 규칙(`min-width: 48rem`)도 걸리지 않았다).
- 겹침 순서(v0.7.0): 고정 머리글·표 머리 = `z-index: 10` · 건너뛰기 링크 = 20(base.css 내장). 서랍·패널·모달은 `<dialog class="sd-layer">` + `showModal()` 로 열어 top layer 에 올린다 — z-index 를 쓰지 않는다. 값 선택 펼침 목록(`.sd-picker`, v0.8.0)도 네이티브 popover 로 top layer 에 올린다. 스크림은 `.sd-layer::backdrop`(잉크 20%, base.css 안 계산값 — 소비처가 투명도를 적지 않는다).
- 화면 가장자리에 붙는 요소(고정 입력창·머리글·서랍)는 `env(safe-area-inset-*)` 만큼 안쪽 여백을 더한다(아이폰 홈 표시줄·노치). 하단에 붙은 화면 키보드 위로 고정 요소를 올린 동안에는 겹치는 아래 safe-area 여백을 빼고(그때는 키보드가 홈 표시줄을 덮는다), 키보드와 고정 요소 사이로 뒤의 페이지가 비치지 않게 한다 — 떠 있는 키보드처럼 하단을 덮지 않으면 여백을 그대로 둔다. 구현은 소비처 몫이다(v0.8.1). **키보드가 올라온 동안의 세로 공간**(v0.11.1): 키보드가 하단을 덮는지는 보이는 영역의 높이(레이아웃 높이와의 차이)로 정하고 입력칸 초점으로 추정하지 않는다. 보이는 높이가 줄면 ① 늘 같은 안내문(입력칸 아래 형식·크기 안내 등) ② 아래 safe-area 여백 ③ 본문 스크롤 영역 ④ 입력칸·첨부 목록의 높이(각자 안에서 스크롤 · 한 줄까지) 순서로 자리를 내준다. 복합 입력의 테두리 상자·도구줄·오류 문구·확인이 필요한 알림은 내주지 않는다. 이 최소 구성만으로도 화면을 넘는 낮은 높이(가로 화면 등)에서는 고정을 풀고 화면 전체를 스크롤해 전송 단추에 닿게 한다. 계기 = 개인 에이전트 화면에서 키보드를 올리자 입력 상자가 눌려 전송 단추 줄이 테두리 밖으로 넘치고 본문 영역이 0 이 된 실측.
- 부품 반응형은 줄바꿈(flex-wrap)을 우선한다. 컨테이너 쿼리는 폭이 정해진 자리에서만 쓴다 — `container-type` 은 폭이 내용으로 정해지는 자리에서 폭을 0 으로 접는다.

## 6. 컴포넌트 스펙 (모양 정본 = base.css · React 껍데기 9종)

모양의 정본은 `registry/ui/base.css` 의 `sd-*` 클래스다(v0.6.0). React 부품은 클래스를 입히는 껍데기(9종)이고 모양을 tsx 에 다시 적지 않는다. **클래스·variant 추가는 이 문서 갱신이 선행 조건**이다 — 페이지별 예외를 부품이 흡수하기 시작하면 시스템이 무너진다.

9종 = PageShell · BackLink · Card · Button(ButtonLink는 Button의 링크형이라 별도로 세지 않음) · Input · Textarea · Badge · Segmented · TableWrap(v0.7.0) — **export 컴포넌트 단위**로 센다. `base.css`·`prose.css`는 스타일 계층이지 프리미티브가 아니다. React 껍데기가 없는 규격(상태 표기·표·접이식 등)은 아래 "CSS 규격" 절에 있고, 클래스를 마크업에 직접 쓴다.

**경계 규칙**(v0.8.2 열거 보강):
- 부품의 시각 선언(색·면·테두리·안쪽 여백·글꼴·글자 크기·줄간격·포커스)은 base.css 만 갖는다. 소비처의 CSS·className·`style` 이 부품 요소에 거는 선언은 배치(폭·위치·최대 높이·간격)뿐이다. 다른 모양이 필요하면 있는 부품·변형을 쓰거나 이 문서에 변형을 먼저 더한다.
- 부품 요소 = `sd-*` 클래스를 단 요소와, 그 클래스 규칙이 모양을 정하는 안쪽 요소(표 칸 등)다. 선택자에 클래스 이름이 없어도 그 요소에 걸리면 해당한다(예: `.x pre` 가 `pre.sd-code` 에 걸림).
- 이 문서가 소비처 몫으로 적은 선언은 그 조항을 따른다(예: 코드 블록 줄바꿈 — 「읽기 전용 결과」 · safe-area 여백 — §5-1 · 끌어놓는 중의 `brand-hover` 면 — 「파일 첨부」). 글꼴 파일 등록(`@font-face`)은 요소 선언이 아니며 소비처 몫이다(§17).
- 부품이 아닌 소비처 자기 요소의 모양은 이 규칙 밖이다. 거기서도 토큰·§4 글자 크기 6단·§1-3-2 넓은 면 금지는 그대로다. 부품과 같은 역할(코드·표·접이식 등)의 요소는 자기 요소로 다시 그리지 않는다(§12).

### PageShell (`.sd-page` · `.sd-measure-reading` · `.sd-measure-narrow`)
모든 페이지의 루트. `width="wide|reading|narrow"`(기본 reading). §5 값 강제.
**2층 구조(v0.5.0)**: 바깥 `<main class="sd-page">`는 항상 wide 중앙 배치(패딩 상 24px · 좌우 24px · 하 56px), 안쪽 div가 `reading`/`narrow` 상한을 왼쪽 정렬로 적용 — 모든 본문이 헤더와 같은 왼쪽 기준선에서 시작(§5). `className`은 바깥 `<main>`이 아니라 안쪽 콘텐츠 레이어에 적용된다.

### BackLink
상세(자식) 페이지 상단 뒤로가기 표준. `.sd-meta` 문단 안 `← {부모 섹션명}` 링크(`sd-target brand-underline` — 링은 `.brand-underline` 에 내장, v0.7.0). `.sd-target`이 텍스트는 text-xs를 유지하면서 터치 타깃 24×24px 구조를 보장한다(v0.5.2). 모든 상세 페이지의 **첫 요소**로 쓰고, 다음 블록은 `mt-3`.

### Card (`.sd-block` · `.sd-block-link` — 구획 블록, 박스 아님)
상단 헤어라인(`line` 1px) + 세로 패딩 20px 으로만 구획(v0.4.0, 사면 박스 금지). `href` 주면 전체 링크(`.sd-block-link`) + 브랜드 호버 틴트(회색 호버 금지) + 내장 포커스 링. 링크 카드의 호버 틴트는 **좌우 8px 확장**(텍스트 기준선은 유지, 틴트만 번짐 — 표준 그리드 `gap-4`에서 인접 카드와 겹치지 않는 상한. v0.5.1). 구성: eyebrow(`.sd-eyebrow`, 선택) → title(`.sd-block-title` = 18px semibold) → description(`.sd-block-desc` = 14px `ink-muted`) → children. 제목·설명의 간격(`mt-2`·`mt-1`)은 배치라 className 에 둔다(v0.7.0). 목록·그리드는 Card를 나열하면 행마다 룰이 생겨 gov.uk식 리스트가 된다.

### Button / ButtonLink (`.sd-btn` · `--ghost` · `--plain` · `--sm` · `--icon`)
- variant: **solid**(잉크 면 + 흰 글자, 호버 = 잉크 80%) · **ghost**(`surface-subtle` 면, 호버 = 브랜드 틴트 — 테두리 없는 면, gov.uk secondary 문법) · **plain**(v0.11.0 — 아래). 3종 외 금지. 호버는 포인터가 있는 기기에서만 걸린다(`@media (hover: hover)`, v0.7.0 — 터치 기기에서 탭한 자리에 틴트가 남지 않게).
- size: **md**(높이 40px · 좌우 16px · `text-sm`) · **sm**(32px · 12px · `text-xs`).
- **한 묶음 안에서는 크기를 섞지 않는다**(v0.7.0): 같은 `.sd-actions` 줄의 버튼은 글자 버튼·아이콘 버튼 모두 같은 크기(md 끼리 · sm 끼리)로 높이를 맞춘다. sm 은 둘레 글자가 작은 자리(표 행·첨부 목록·코드 복사 단추)에만 쓰고, 그 자리의 버튼은 모두 sm 이다. 그 버튼이 시작한 제자리 확인의 단추도 sm 이다(아래 행동 패턴 v0.10.1). 글자 버튼의 폭은 글자 길이를 따르고 아이콘 버튼은 높이와 같은 정사각이다.
- **버튼 글자는 줄바꿈하지 않는다**(v0.7.1, base.css `white-space: nowrap`): 높이가 고정이라 꺾이면 글자가 버튼 밖으로 넘친다. 자리가 모자라면 배치(버튼 줄 넘김·옆 칸 줄이기)로 푼다. 계기 = 휴대폰에서 긴 제목 옆 「수정」 단추가 두 줄로 꺾인 실측(2026-10-29).
- **icon**(v0.6.0): 아이콘 전용 정사각(md 40 · sm 32). 보이는 글자가 없으므로 **`aria-label` 필수**(React 는 타입으로 강제). 아이콘 규격은 아래 "아이콘".
- **plain**(v0.11.0, `.sd-btn--plain`) = 평소 면이 없는 아이콘 단추. 호버(포인터 기기)·누름·키보드 포커스 때만 `brand-hover` 면이 보인다. 아이콘 단추(`--icon`)와만 쓴다 — 글자 단추는 면이 없으면 단추로 읽히지 않는다(React 는 타입으로 강제). 크기·투명 1px 테두리·포커스 링·비활성은 다른 변형과 같다. **자리로 고른다**: 페이지 머리글 안의 아이콘 단추(서랍을 여는 메뉴 단추 등)는 plain 이다. 떠 있는 층 머리의 닫기 · 입력칸 옆(첨부 등) · 떠 있는 단추(맨 위로 등) · 목록·표 행 안의 아이콘 단추는 ghost 면을 유지한다 — 글이나 입력 둘레 위에서는 면이 있어야 누를 자리가 보인다. 같은 화면에서 한 단추만 면을 빼는 식으로 고르지 않는다(자리가 같으면 모양도 같다). 머리글 맨 앞에 둘 때의 정렬은 §5-1 「머리글 맨 앞 요소」. 근거 = Apple HIG Toolbars(툴바 항목에 테두리 면을 두지 않는다) · Material 3 top app bar(아이콘 단추 평소 면 없음). 계기 = 개인 에이전트 화면의 좁은 폭 머리글에서 회색 면 메뉴 단추가 왼쪽 시작선을 하나 더 만든 실측(2026-11-12 소유자 결정).
- 공통: `font-medium`·색 전환·내장 포커스 링(직각). 투명 1px 테두리를 갖는다(강제 색상 모드에서 면이 시스템 색이 되어도 버튼 경계가 남는다).
- **비활성 = 네이티브 `disabled` 또는 `aria-disabled="true"`** 를 흐리게 한다(`opacity-40` + 포인터 차단, v0.7.4). `aria-disabled` 는 포커스가 단추에 남아야 할 때(요청 중 단추 — §16-9) 쓰고, 키보드 실행 차단은 소비처 스크립트가 맡는다.
- 링크가 버튼처럼 보여야 하면 ButtonLink(기본 ghost).
- 버튼 묶음은 `.sd-actions`(가로 줄바꿈, 간격 8px). 크기 혼용 금지는 위 size 규칙.

### Input / Textarea (`.sd-field`)
굵은 잉크 2px 테두리 · 투명 배경 · 패딩 6px/12px(Textarea 는 8px/12px) · `text-base`(16px — 아이폰 입력 확대 방지, v0.7.0) · placeholder `ink-faint` · 내장 포커스 링(직각 — **굵은 잉크 테두리는 "입력하는 곳"이라는 기능 신호**, gov.uk 문법. v0.4.0). Textarea 는 최소 높이 112px · 세로 크기 조절. 셀렉트는 `select.sd-field`(직각 화살표를 그리고, 강제 색상 모드에서는 네이티브 화살표로 되돌린다). 라벨은 `.sd-label`(`text-xs font-medium text-ink-muted`) + `gap-2`.

**한 줄 입력칸의 높이 = 버튼 md 40px**(v0.7.3): 한 줄 글 입력칸(`input.sd-field`)과 버튼이 한 줄에 놓이면(검색칸 + [검색], 찾기칸 + 이전·다음 아이콘 단추) 높이가 같아야 한다. base.css 가 테두리 2 + 여백 6 + 줄 24 + 여백 6 + 테두리 2 로 40px 를 맞춰 두고(여백 = `calc(0.5rem - 2px)` 라 기본 글자 크기를 키워도 버튼 2.5rem 과 같이 커진다), 소비처는 높이·여백을 다시 적지 않는다. 정하지 않은 것: 셀렉트(`select.sd-field`)는 브라우저가 높이를 정하는 부분이 있어(강제 색상 모드의 네이티브 모양 포함) 이 보장에 넣지 않는다 — 버튼 옆에 셀렉트를 두는 소비처가 생기면 그때 Safari·Chrome 에서 재고 정한다. 입력칸 옆 버튼은 md 를 쓴다(sm 32px 는 입력칸과 한 줄에 두지 않는다 — 위 「한 묶음 안에서는 크기를 섞지 않는다」의 연장). 계기 = v0.7.0 에서 입력칸 글자를 16px 로 올리며 한 줄 입력칸이 44px 가 되어 옆 버튼(40px)과 어긋난 실측(개인 대시보드 검색칸 2곳, 2026-10-30).

상태: disabled = `opacity-40`(버튼과 같은 값) · **에러 = `aria-invalid="true"` → 테두리만 `error`**(v0.6.0) · 포커스 = 내장 링.

**읽기 전용 결과(v0.7.0)**: 변환·계산 결과처럼 사용자가 고치지 않는 글은 입력칸 모양(잉크 2px = "입력하는 곳")을 쓰지 않는다 → `pre.sd-code` + 바로 아래 `.sd-actions` 의 복사 단추(`.sd-btn--ghost.sd-btn--sm`). 긴 한 줄 결과는 코드 블록 안에서 가로로 스크롤된다 — 줄바꿈이 꼭 필요하면 그 화면에서 `white-space: pre-wrap`(긴 낱말이 넘치면 `overflow-wrap: anywhere` 도)을 배치 선언으로 둔다. `readonly` 입력칸은 "값을 보여 주되 폼과 함께 제출되는" 칸에만 쓴다.

**칸 오류 문구(`.sd-error-msg`)**: `text-sm font-medium` + `error` 글자. 마크업 앞에 `<span class="sd-vh">오류:</span>` 를 붙이고(화면에는 숨고 화면낭독기에는 읽힌다), 문구의 `id` 를 해당 입력의 `aria-describedby` 로 연결한다 — 어느 입력의 오류인지가 계약의 일부다(v0.5.1). 오류가 나도 입력값은 지우지 않는다. 넓혀 말하면(v0.8.1) 사용자가 넣은 글·첨부는 앱이 말없이 버리지 않는다: 성공이 확인된 전송분만 비우고, 화면을 스스로 다시 읽어야 하면(새 판 적용·자동 새로고침) 입력이 빈 때로 미룬다. 제출 시 오류가 하나 이상이면 아래 "인셋 안내"의 오류 요약을 쓴다(v0.7.0 — §16-9 와 같은 조건). **예외 = 칸이 하나뿐인 입력**(v0.11.0 — 대화 입력창·한 칸 검색처럼 제출할 칸이 하나인 폼): 오류 요약을 쓰지 않고 그 칸 바로 아래 `.sd-error-msg` 에 `role="alert"` 를 주며, 포커스를 옮기지 않는다(글을 쓰던 자리에서 포커스를 빼앗지 않는다 · 가리킬 칸이 하나라 요약 목록이 필요 없다). 입력칸에서 제출했으면 포커스는 입력칸에 남고, 제출 단추에서 제출했으면 포커스는 그 단추에 남고, 응답을 기다리는 사이 사용자가 다른 곳으로 옮겼으면 그대로 두고 문구만 알린다. 문구 틀은 §16-6 오류 「무엇이 · 왜(알면) · 다음 행동」이고, 브라우저 원문 오류를 그대로 보이지 않는다. 다음 제출이나 입력 수정으로 오류가 풀리면 문구를 치운다.

### Badge (`.sd-badge`)
**분류 꼬리표 전용.** `surface-subtle` 면 · 패딩 2px/8px · `text-xs text-ink-muted`(직각 — 알약형 금지). 상태(실패·주의 등)를 말하지 않는다 — 상태는 아래 "상태 표기"(v0.6.0).

### Segmented (`.sd-tabs` + `.sd-tab` · v0.6.0)
값 하나를 고르는 토글 버튼 묶음(`aria-pressed`). **그룹 라벨 필수**(`label`, 모양 `.sd-label`) — 앞 제목이 맥락을 주는 자리에서만 `hideLabel` 로 화면에서 숨긴다(화면낭독기에는 읽힌다). 모양은 아래 "탭·세그먼트". 선택지는 7개 상한이고, 5개를 넘거나 한 줄에 들어가지 않으면 `select.sd-field` 나 값 선택 펼침 목록(`.sd-picker`, v0.8.0)을 먼저 검토한다.

### TableWrap (`.sd-table-wrap` · v0.7.0)
넓은 표의 가로 스크롤 상자. `label`(필수) 을 받아 `tabIndex={0}` + `role="region"` + `aria-label` 을 함께 붙인다 — 셋 중 하나라도 빠지면 키보드 스크롤이나 상자 이름이 깨지므로 묶어서 준다. 안의 표는 `<table className="sd-table">` 그대로.

### CSS 규격 (v0.6.0 — React 껍데기 없이 클래스를 직접 쓴다)

**상태 표기(`.sd-status` · `--error` · `--attention`)** — 뜻 이름 글자가 주인이고 색·표지는 보조다.
- 기본(표지 없음) = 정상·진행·완료·업무 상태, `ink-muted`.
- `--error` = 오류·실패: `error` 글자 + 굵게 + 채운 8px 사각.
- `--attention` = 살펴볼 것·판정 불가: `attention` 글자 + 굵게 + 빈 8px 사각(2px 테).
- 표지는 `border` 로 그린다(강제 색상 모드에서도 남는다). 면으로 상태를 칠하지 않는다. 공통 부품은 상태를 추론하지 않는다 — 소비처가 뜻을 정해 넘긴다.

**인셋 안내(`.sd-callout` · `--strong` · `--error` · `--attention`)** — 좌측 2px 선 + 왼쪽 들여쓰기 12px. 기본 = `line`(보조 주석) · `--strong` = 잉크(꼭 읽을 안내·제자리 확인) · `--error`·`--attention`.
- **`--error`·`--attention` 은 첫 줄에 같은 뜻의 `.sd-status` 문구를 둔다**(선 색만으로 갈리지 않게 — WCAG 1.4.1).
- 오류 요약 = `--error` 안에 고정 제목 「확인할 것이 있습니다」 + 오류 칸으로 가는 링크 목록, `role="alert"`. 오류가 하나 이상이면 쓴다(칸이 하나뿐인 입력은 예외 — 위 「칸 오류 문구」, v0.11.0). 나타날 때 제목(`tabindex="-1"`)으로 포커스를 옮긴다. 사면 박스 금지.
- 화면 전체에 걸린 알림(점검 공지 등)은 PageShell 안 첫 요소 `.sd-callout`(또는 `--attention`)으로 둔다. 화면 위에 띄우는 배너는 만들지 않는다(v0.7.0).

**표(`.sd-table` · `.sd-table-wrap` · `.sd-table--stack` · `.sd-row-note` · `.sd-num` · `.sd-row--idle`)**
- 본문 열 폭을 넘을 수 있는 표는 모두 `.sd-table-wrap`(가로 스크롤 상자) 안에 둔다(v0.7.0 — "넓은 표"의 뜻). 상자에 `tabindex="0"` + `role="region"` + `aria-label` 을 준다(React = `TableWrap`). 좁은 화면 전략은 이것이 기본이다.
- **쌓기 변형 `.sd-table--stack`**(v0.9.0 — v0.8.1 의 「행을 쌓아 보일 수 있다」 예외를 대체): 주 목록 표(화면의 주 내용이 목록이고 행 제목 칸 `.sd-row-title` 을 가진 표, §4)에만 붙인다. 48rem 미만(§5-1)에서 행을 쌓는다. 칸 여백·테두리 초기화, 행 위아래 여백과 아래 `line` 1px, 머리 숨김은 변형이 갖고, 칸의 자리(줄 나누기·간격)만 소비처 몫이다. 소비처의 배치 쿼리도 같은 경계(`(width < 48rem)`, v0.11.0)를 쓴다.
  - 제목·조작·메타를 줄로 나눠 놓을 수 있다. 한 줄 안의 칸은 마크업 순서대로 놓는다(화면 순서와 읽기·포커스 순서가 어긋나지 않게).
  - 쌓인 동안(48rem 미만)에만 보조 칸을 뺄 수 있다. 넓은 화면에서는 칸을 빼지 않는다. 조건: 행 제목·상태·조작 칸은 늘 보인다 · 뺀 값은 그 행이 여는 화면에서 볼 수 있다(`title` 툴팁만으로는 안 된다) · 같은 목록을 거른 결과도 같은 칸을 뺀다.
  - 같은 목록을 거른 결과(검색 결과 등)도 이 변형을 쓴다. 행마다 늘 붙는 내용(검색 발췌 등)은 따로 행을 만들지 않고 제목 칸 안에 둔다.
  - 머리는 숨기므로 정렬은 넓은 화면에서 한다(숨긴 정렬 단추가 보이지 않는 채로 포커스를 받지 않게 통째로 숨긴다).
- **보조 행 `tr.sd-row-note`**(v0.10.0): 행 조작 뒤 잠시 붙는 제자리 확인·결과 문구(아래 행동 패턴)를 그 행 바로 아래에 둘 때 쓴다. 칸은 하나(`td` 에 `colspan` = 전체 칸 수)이고 안에 확인 구획·결과 문구를 넣는다. 앞 행과 한 덩어리로 보이게 앞 행의 아래 선을 지우고 보조 행 아래에 행 선을 두며, 위 여백 0 · 아래 여백 4px 이다(쌓인 표에서는 행 선과 행 아래 여백을 쌓기 변형에서 받는다). 이 모양은 base.css 가 갖고, 소비처는 보조 행을 넣고 빼는 일만 한다 — 앞 행이 목록에서 사라지면 보조 행도 치우고, 앞 행이 숨으면 확인은 취소하고 결과 문구는 함께 숨긴다(다시 보이면 결과 문구도 다시 보인다).
  - 행마다 늘 붙는 내용(검색 발췌 등)에는 쓰지 않는다 — 그런 내용은 제목 칸 안에 둔다(위 쌓기 변형 조건). 보조 행은 행 조작의 확인·결과처럼 잠시 생겼다 사라지는 내용 전용이다.
  - 정렬은 행 단위로 하므로, 정렬하거나 목록을 다시 그릴 때 보조 행은 앞 행에 붙여 옮기거나 치운다(소비처 몫).
- 헤더 면 없음: `thead th` = `font-medium` · `ink-muted` · 아래 **잉크 1px**(머리·몸 경계) · 행 = `line` 1px.
- 머리 규칙은 `thead` 안의 `th` 에만 걸린다(v0.6.1). 몸통의 행 머리 `th` 는 `td` 와 같은 칸(행 `line` 1px)이고 `font-medium` 왼쪽 정렬만 갖는다 — 그 안의 단추는 정렬 단추 초기화를 받지 않는다.
- `.sd-num` = 오른쪽 정렬 + Geist Mono(`--font-mono`, v0.7.0) + `tabular-nums` · 모르는 값은 「—」. 숫자 칸은 머리 `th` 와 몸 칸에 함께 붙인다.
- 메타 칸(시각·기간·ID 등 행의 보조 값)은 칸에 `.sd-meta`(12/16 · `ink-faint`)를 붙인다(v0.9.0). 숫자 메타 칸은 `.sd-meta.sd-num`. 칸 글자 크기·색을 소비처 CSS 에 따로 적지 않는다(경계 규칙).
- `.sd-row-title` = 주 목록 행 제목 칸 16/24(v0.8.0 · 붙이는 기준은 §4). 칸의 글자 크기는 소비처 CSS 에 적지 않는다(경계 규칙).
- 정렬 = `thead th` 안 `<button>`(높이 24px 이상) + `th` 의 `aria-sort`(화살표는 보조).
- 업무상 유휴 행 = `.sd-row--idle`(`ink-muted`). 비활성 컨트롤이 아니므로 opacity·`ink-faint` 로 흐리지 않는다.
- 고정 머리(sticky)를 쓰면 `th` 배경을 불투명한 `surface` 로 둔다(아래 행이 비쳐 겹치지 않게). `.sd-table-wrap` 은 `overflow-x: auto` 때문에 세로로도 스크롤 상자가 되어 sticky 기준이 화면에서 상자로 바뀐다 → 고정 머리를 쓰는 표는 상자에 높이를 정해 세로 스크롤도 상자가 갖게 하거나(예: `max-height: calc(100dvh - 머리글 높이)`), 가로 넘침이 없는 표면 상자를 쓰지 않는다.

**접이식(`.sd-details`)** — 네이티브 `<details>`/`<summary>`. 좌측 2px `line` + 머리줄 `text-xs ink-muted` + `›`/`⌄`.
- 머리줄 문구가 안의 상태를 요약한다(「도구 3개 실행 · 1개 실패」).
- **안에 실패가 있으면 머리줄의 그 조각을 `.sd-status--error` 로 쓴다**(닫힌 머리줄에서 실패가 정상과 같은 무게로 묻히지 않게). 펼칠지는 실패의 성격으로 정한다(v0.6.1):
  - **결과인 실패**(그 실패로 일이 끝남 — 마지막 단계가 실패, 또는 전체가 실패) = 기본으로 펼친다(`open`). 전체가 실패면 접이식 밖에 `.sd-callout--error` 로도 알린다.
  - **과정인 실패**(뒤에 다른 시도가 이어짐) = 머리줄의 「실패」 표시만 두고 접어 둔다.
  - 판정은 일어난 사실(뒤에 단계가 이어졌는가)로만 한다. "복구됨"을 추론해 표시하지 않는다(§16-4).
  - 판정 시점(v0.7.0) = 그 묶음이 끝났다는 신호(응답 종료 이벤트)를 받은 때다. 스트리밍 중에 실패가 오면 머리줄에 「실패」만 표시하고, 종료 신호 때 결과인 실패면 펼친다. 사용자가 직접 열거나 닫은 접이식은 그 뒤 자동으로 바꾸지 않는다.
- 머리줄 안의 `.sd-status` 는 한 줄로 고정된다(`flex: none` · `white-space: nowrap`, v0.6.1 — 한글은 음절마다 줄바꿈이 허용되어 줄어드는 칸에 두면 「실/패」로 쪼개진다). 줄어드는 칸은 하나(인자·경로 등)만 두고 그 칸에 `min-width: 0` 과 말줄임을 준다. 순서 = 이름 · 상태 · 인자.
- `summary` 에 `aria-label` 을 달지 않는다(안의 문구를 가린다).

**목록 행(`.sd-list` · `.sd-list-item`)** — 선택 가능한 행. `<a>`·`<button>` 모두 쓸 수 있다(버튼 초기화 내장: 테두리·배경 없음, 폭 100%, 왼쪽 정렬, 글꼴 상속). 제목 `text-sm` + 메타 `.sd-meta` · 호버 `brand-hover`(포인터 기기만) · 선택 = `aria-current` → 잉크 좌측 2px + 굵게. Card(구획 블록)와 다르다. 좌측선은 화면에 펼쳐진 목록(사이드바·탐색 목록)의 "지금 위치" 표시다 — 값 선택 펼침 목록 안의 행은 좌측선 대신 체크를 쓴다(아래, v0.8.0).

**값 선택 펼침 목록(`.sd-picker`, v0.8.0)** — 단추를 누르면 펼쳐지는 값 고르기 목록(예: 새 세션의 모델). 기본 선택 상자(`select.sd-field`)의 OS 펼침 모양이 맞지 않는 자리에 쓴다.
- 구조: 트리거 = `.sd-btn`(지금 값을 글자로 보인다 · `aria-expanded`) · 목록 = `<div class="sd-picker" popover role="group" aria-label="{무엇을 고르는지}">` · 항목 = `<button class="sd-list-item" aria-pressed>`. 네이티브 popover 라 top layer 에 뜨고(z-index 없음), 바깥을 누르거나 Esc 를 누르면 닫힌다.
- 모양(base.css): 사면 잉크 1px + 바탕 `surface` + 안쪽 여백 4px(떠 있는 층과 같은 문법, 그림자 없음) · 항목 높이 40px · 14px · 한 줄. **선택 = 글자 앞 잉크 체크 + 굵게(500)**, 좌측선 없음. 체크는 테두리로 그리고, 항목 글자에 「✓」를 넣지 않는다(글자 = 값 이름). 비선택 항목 글자는 잉크 그대로다. 위치·최소 폭·공간이 모자랄 때의 최대 높이와 스크롤은 배치라 소비처 몫이다.
- 행동 계약: 값 하나를 고르는 단추 묶음(Segmented 와 같은 `aria-pressed` 계약 — 방향키를 만들지 않는다, Tab 으로 항목을 오간다) · 펼치면 선택된 항목으로 포커스 · 고르거나 Esc 로 닫으면 트리거로 포커스 복귀 · 바깥 누름으로 닫히면 포커스를 옮기지 않는다.
- 동작 목록(메뉴 — 「복사」·「삭제」처럼 누르면 일이 일어나는 목록)에는 쓰지 않는다(§13).
- 계기 = 모델 목록의 좌측 선택선이 작은 상자 안에서 스크롤 막대처럼 보인 실측과, 기본 선택 상자는 sidoyu 모양과 어울리지 않는다는 소유자 결정(개인 대시보드, 2026-11-02).

**탭·세그먼트(`.sd-tabs` · `.sd-tab`)** — 같은 모양. 선택 = `aria-selected`/`aria-pressed`/`aria-current` → 잉크 2px 밑줄(묶음의 `line` 1px 위에 겹침) + 굵게. 브랜드로 선택을 표시하지 않는다. `.sd-tab` 은 언제나 `.sd-tabs` 안에 둔다.
- 탭 = 내용 전환. `role="tablist"` + 방향키 동작을 소비처가 소유한다.
- 세그먼트 = 값 선택. `aria-pressed` 단추 묶음 + 그룹 라벨 의무(React `Segmented`).
- 7개 상한(5개를 넘으면 셀렉트를 먼저 검토).

**복합 입력(`.sd-composer`)** — 입력창 + 도구줄. 바깥 2px 잉크 테두리. **바깥 묶음은 포커스 링을 받지 않는다**(v0.6.1 — 포커스 링 내장 원칙의 유일한 예외): textarea 의 글자 커서가 포커스 표시이고, 굵은 잉크 테두리가 이미 "입력하는 곳"을 알린다(claude.ai·chatgpt.com 의 입력창과 같은 문법). 안쪽 textarea 는 테두리가 없고, outline 은 지우지 않고 투명으로 둔다(강제 색상 모드에서 보인다, v0.7.0). `caret-color` 는 바꾸지 않는다. 안쪽 버튼은 각자 `:focus-visible` 링을 갖는다. 도구줄 = 안쪽 `.sd-actions` 이고 한 줄로 고정된다(전송 단추가 줄바꿈으로 입력창 아래로 밀려나지 않게 — 줄어드는 칸은 소비처가 하나만 둔다). **테두리 상자는 안의 최소 높이(입력칸 한 줄 + 도구줄, 첨부 목록이 있으면 그 한 줄)보다 작게 줄이지 않는다**(v0.11.1) — 공간이 모자라면 줄어드는 것은 상자 안의 스크롤 칸(입력칸·첨부 목록)뿐이다. 테두리 밖으로 안의 요소가 넘치면 상자가 무너진 것이다(§5-1 키보드가 올라온 동안). **링을 빼는 기준**: 글 입력칸이 화면에 하나뿐이고 늘 같은 자리에 있다. 이 기준에 맞지 않는 입력칸은 `.sd-field`(링 내장)를 쓴다. 접근성 근거는 §9.

**코드(`.sd-code`, v0.6.1)** — 인라인 `<code>` 와 블록 `<pre>` 에 같은 클래스를 쓴다. 면 = `surface-subtle`, 직각, 고정폭 글꼴(`--font-mono`). 크기(v0.7.0): 인라인은 둘레 글자 크기를 그대로 받고, 블록은 14px · 줄간격 1.55(§4 예외). 블록의 넓은 면은 §1-3-2 의 예외다. 블록은 줄을 바꾸지 않고 상자 안에서 가로로 스크롤한다 — 키보드로도 스크롤할 수 있게 블록에 `tabindex="0"` + `role="region"` + `aria-label`(예: 「코드」, 언어를 알면 「코드 · python」)을 준다(표 스크롤 상자와 같은 규격, 링 내장. 넘침을 감지해 붙였다 뗐다 하지 않는다). 블록 안의 `<code>` 는 면·여백을 다시 갖지 않는다. 복사 단추는 블록 바로 위나 아래의 `.sd-actions` 안에 `.sd-btn--ghost.sd-btn--sm` 으로 둔다(코드 위에 겹쳐 띄우지 않는다).

**읽기판(`.sd-readout`)** — `<dl>` 안 `<div>` 행마다 `dt`(`ink-muted`, 7rem)·`dd`(잉크), 행 아래 `line` 1px. 폭이 모자라면 값이 라벨 아래로 내려간다(flex-wrap). KPI 숫자에 브랜드 밑줄을 쓰지 않는다.

**폼 컨트롤** — 체크박스·라디오·`progress` = 네이티브 + `accent-color: ink`. 체크·라디오는 공통 포커스 링을 내장한다. 셀렉트 = `select.sd-field`(값을 고르는 드롭다운은 먼저 이것을 검토하고, OS 펼침 모양이 맞지 않는 자리면 값 선택 펼침 목록 `.sd-picker` 를 쓴다 — v0.8.0). 라벨을 포함한 클릭 영역은 24px 이상.

**슬라이더(`.sd-range`, v0.7.0)** — `input[type=range]` 에 붙인다. 트랙 = `line` 2px, 손잡이 = 잉크 12×20px 사각. 포커스 링은 손잡이가 그리고(공통 링과 같은 값), outline 은 투명으로 남긴다. sidoyu.com 의 `.range-ink` 를 옮겨 왔다 — 소비처는 자기 사본을 지운다.

**아이콘(`.sd-icon` · `.sd-btn svg`)** — 크기 20px(sm 버튼 안 16px) · `fill: none` · 획 `currentColor` 1.75 · 획 끝·이음 직각(`stroke-linecap: square` · `stroke-linejoin: miter`) · 장식이면 `aria-hidden`. 이 값은 base.css 가 갖는다(v0.7.0 — 소비처가 다시 적지 않는다). 아이콘 세트는 채택하지 않는다(§13).

**보조 클래스** — `.sd-meta`(`text-xs ink-faint` 메타) · `.sd-eyebrow` · `.sd-label` · `.sd-target`(홀로 선 링크·작은 컨트롤의 24×24 타깃) · `.sd-vh`(화면에 숨기고 화면낭독기에 읽힘 — 키보드 포커스를 받으면 드러난다, 건너뛰기 링크용) · `.sd-actions`(버튼 묶음).
- `.sd-vh` 는 절대 위치라, 기준 위치(`position` 이 static 이 아닌 조상)가 없으면 문서 첫 화면을 기준으로 놓인다. 스크롤 상자 안 아래쪽에 있는 숨김 글자가 상자 밖 문서 높이를 늘려 화면 전체가 밀린다. 그래서 안에 `.sd-vh` 를 두도록 정한 부품(`.sd-user-turn` 의 「나:」 · `.sd-error-msg` 의 「오류:」)은 base.css 가 기준 위치(`position: relative`)를 준다(v0.11.0). 부품 밖(소비처 자기 요소)에서 스크롤 상자 안에 `.sd-vh` 를 쓰면, 소비처가 가까운 조상에 기준 위치를 둔다. 계기 = 긴 대화 아래쪽에 생긴 발화의 「나:」가 문서를 늘려 머리글이 화면 밖으로 밀린 실측(개인 에이전트 화면).

**떠 있는 층(`.sd-layer`, v0.7.0)** — 서랍·패널·모달. 네이티브 `<dialog class="sd-layer">` 에 붙이고 `showModal()` 로 연다. 바탕 `surface` + 사면 잉크 1px(그림자 대신) + 안쪽 여백 24px. 스크림 = `::backdrop`(잉크 20%). 위치·폭·높이(오른쪽 서랍 등)는 배치라 소비처 몫. 행동 계약: 열면 첫 조작 요소로 포커스 · Esc 로 닫힘(네이티브) · 닫으면 연 단추로 포커스 복귀 · 닫힌 층은 탐색 순서에서 빠진다(네이티브 dialog 가 보장). 정보 탐색 서랍은 "확인 모달"(§13 제외)과 별개다. 층 머리(v0.7.1) = 제목 · 부가 동작(받기 등 주소로 가는 것)은 밑줄 링크 `.brand-underline .sd-target` · 닫기 = 아이콘 단추 md(`aria-label="닫기"`). 머리에 글자 단추를 두면 닫기 단추와 같은 크기여야 한다(위 「한 묶음 안에서는 크기를 섞지 않는다」).

**대화의 사용자 발화(`.sd-user-turn`, v0.7.0)** — `surface-subtle` 면 + 직각 + 안쪽 여백 10px/14px(폭 상한에 포함 — `border-box`) + 16px 글자 · 줄간격 24px, 테두리·그림자 없음. 면 안의 글은 왼쪽 정렬(여러 줄을 오른쪽 정렬하지 않는다). 배치는 소비처 몫: 오른쪽 끝(`align-self: flex-end` 등) · 폭 상한 85%(좁은 화면 92%) · 첨부 목록도 오른쪽. 발화마다 앞에 `<span class="sd-vh">나:</span>` 를 둔다. 답(어시스턴트 글)은 면·라벨 없이 왼쪽 기준선에서 `.sd-prose` 로 쓴다. 근거 = §16-8. 줄간격은 단위 없는 1.5 다(v0.8.0 — §4).
- **마크다운을 그린 발화 = `.sd-user-turn--md`**(v0.8.0): 원문 글자 그대로의 발화는 `pre-wrap` 이고, 마크다운을 HTML 로 그린 발화는 이 변형을 함께 붙여 줄바꿈을 HTML 에 맡긴다(`white-space: normal` — 빈 줄이 덧붙지 않게). 안쪽 제목(h1~h6)은 모두 본문 크기 16px + 굵기 600 이다 — 발화는 짧은 글이라 답의 제목 크기(24·18)를 쓰지 않는다. 문단·목록·제목 아래 8px · 목록 들여쓰기 24px · 굵게 600 · 구분선 = `line` 1px. 계기 = 발화 안의 `# 제목`(32px)이 고정 줄간격 24px 를 물려받아 윗줄과 겹친 실측(개인 대시보드).

**긴 글(`.sd-prose`, v0.7.0)** — 일반 CSS·생성 HTML 용 긴 글 규격(Tailwind typography 를 쓰는 소비처는 `.prose` + prose.css). 16px · 줄간격 1.75 · 문단·목록 아래 12px · 제목 h1~h4 = 24 bold / 18 · 16 · 14 semibold · `hr` = `line` 1px · 인용 = `.sd-callout` 과 같은 모양 · 링크 = `.brand-underline` 과 같은 모양(링 내장). 표·코드·접이식은 안에서도 각자의 `sd-*` 규격을 쓴다. 안쪽 규칙은 우선순위가 0(`:where()`)이라 본문 안에 놓인 `sd-*` 부품(버튼·목록·인셋 변형)이 언제나 이긴다.

### 행동 패턴 (클래스 조합 — 새 클래스 없음)

- **진행 표시** — 「{동사} 중…」 문구에 `role="status"` 를 주되, **초마다 바뀌는 경과초는 live region 밖에 둔다**. 화면낭독기에는 시작·완료·실패만 알린다. 검색 완료·결과 0건도 `role="status"` 로 알린다. 스켈레톤 자체는 낭독하지 않고(`aria-hidden`) 로딩 문구로 알린다(v0.7.0).
- **건너뛰기 링크**(v0.7.0) — 사이드바가 본문 앞에 오는 작업 화면의 첫 요소 = `<a class="sd-vh brand-underline" href="#본문id">본문으로 건너뛰기</a>`. 평소에는 숨고 키보드 포커스를 받으면 왼쪽 위에 드러난다. 누르면 본문(`tabindex="-1"`)으로 포커스가 옮겨진다(KRDS 건너뛰기 링크 규칙).
- **파일 첨부**(v0.7.0, 새 클래스 없음) — 첨부 단추 = 실제 `.sd-btn`(숨긴 `input[type=file]` 을 단추가 연다 · 끌어놓기는 보조 경로) · 허용 형식·크기를 첨부 전에 안내 · 끌어놓는 중 = 놓을 자리에 `brand-hover` 면 · 첨부 목록 = 항목마다 파일명 + `.sd-meta`(크기·「올리는 중…」) + 실패면 `.sd-status--error` + 빼기 단추 `.sd-btn--icon.sd-btn--sm`(`aria-label="{파일명} 빼기"`) · 빼면 포커스를 다음 항목의 빼기 단추로 옮긴다 — 다음 항목이 없으면(마지막 항목을 뺐으면) 앞 항목, 목록이 비면 첨부 단추(v0.11.0 — 옛 문구 「없으면 첨부 단추」를 「남은 항목이 없으면」으로 읽을 수 있어 뜻을 풀어 적었다) · 거절 사유는 입력창 아래 `.sd-error-msg`(토스트 아님). 썸네일 크기는 배치다. Badge 는 분류 꼬리표 전용이라 첨부에 쓰지 않는다.
- **제자리 확인**(모달 없음) — `.sd-callout--strong` + `.sd-actions`. 확인 구획이 열리면 포커스를 옮기고, 취소·완료·Esc 면 원래 버튼으로 되돌린다 — 완료 때는 포커스가 아직 그 흐름 안에 있을 때만 되돌리고 결과를 보이게 올린다. 그사이 다른 흐름으로 옮겨 갔으면 포커스·스크롤을 건드리지 않고 결과 문구만 남겨 `role="status"` 로 알린다(v0.8.1). 포커스 대상(v0.7.2): 되돌릴 수 있는 행동(아래 「파괴적 행동」의 구분)은 **실행 단추** — 여는 단추를 누르고 Enter 로 바로 실행된다. 질문·경고·설명 문장은 한 구획으로 묶어 실행 단추의 `aria-describedby` 로 함께 읽히게 한다(미리보기 전문은 빼고). 되돌릴 수 없는 행동은 질문 문장(`tabindex="-1"`). Enter 를 누른 채 있는 키 반복(`repeat`)으로는 실행하지 않는다. 미리보기처럼 긴 내용이 있으면 단추 줄을 그 위(설명 다음)에 둔다. 실행 중 반복 실행을 막는다. 흐름 안 결과 문구에는 `role="status"`. 확인 구획과 결과 문구가 고정 요소(머리글·고정 입력창)에 가리면 보이는 곳으로 올린다 — 단추 줄을 먼저 보이게 한다(v0.8.1). 제자리 확인은 한 번에 하나만 연다(v0.8.1): 다른 확인을 열면 아직 실행하지 않은 앞의 확인은 접고, 포커스는 앞 단추로 되돌리지 않고 새 확인의 포커스 대상에 둔다. 이미 실행한 요청의 진행·결과 문구는 그대로 남긴다. 표 행의 조작이면 확인 구획과 결과 문구를 그 행 바로 아래 보조 행(`tr.sd-row-note`, v0.10.0 — 위 표 조항)에 둔다. 단추 크기(v0.10.1): 확인 구획의 단추는 그 흐름을 시작한 단추와 같은 크기(md·sm)다. 응답으로 이어 열린 다음 단계 확인도 처음 누른 단추를 따른다. 폭·아이콘 모양·solid/ghost 는 따르지 않는다. 시작한 단추가 없거나 크기 등급이 없는 요소(링크·목록 행·메뉴 항목·단축키·자동 확인)면 md 다. 한 줄 입력칸과 같은 줄의 단추는 언제나 md 다. 계기 = 옛 팝업의 「누르고 Enter」 흐름이 제자리 확인에서 끊긴 실측(개인 대시보드의 [세션 잇기], 2026-10-30).
- **대화 본문(에이전트·모델이 쓴 마크다운)**(v0.6.1) — 기존 규격에 대응시킨다: 문단·목록·제목·구분선 → `.sd-prose` 안(v0.7.0) · 표 → `.sd-table-wrap` + `.sd-table` · 인용 → `.sd-callout`(`.sd-prose` 안 `blockquote` 는 같은 모양) · 링크 → `.brand-underline` · 코드 → `.sd-code` · 접이식 → `.sd-details` · 그림 → 열 폭을 넘으면 줄이고 작은 그림은 키우지 않음 · 누르면 원본 · 옆에 받기 단추 `.sd-btn--ghost.sd-btn--sm`(v0.7.0) · 대체 글(v0.8.1) = 원문에 설명이 있으면 그대로 쓰고, 없으면 위치를 알리는 글(「첨부 그림 1」 등)을 둔다 — 그림을 가리키는 이름일 뿐 내용을 대신하지는 못한다. 빈 `alt=""` 는 장식 그림에만 쓴다. 원시 HTML 은 해석하지 않고 글자로 보인다. 역할 구분은 §16-8(사용자 발화 = `.sd-user-turn`).
- **검색 강조**(v0.8.1, 새 클래스 없음) — 찾은 낱말은 `<mark>` 로 감싸고(글자 노드 안쪽에 넣는다 — 다른 요소를 감싸지 않는다), 지금 위치 하나에만 `aria-current="true"` 를 준다(클래스로 지금 위치를 표시하지 않는다). 색은 base.css 의 `mark` 규칙이 갖고 소비처는 다시 적지 않는다. 지금 위치는 색만으로 알리지 않는다 — 「3 / 12」 같은 위치 문구를 함께 보인다. 찾기를 닫으면 `mark` 를 걷어 원래 글로 되돌린다.
- **닫을 수 있는 확인 알림**(v0.11.1, 새 클래스 없음) — 화면을 다시 열어도 남아야 하는 「확인 필요」 알림(예: 다시 연 화면에서 이전 첨부를 되살리지 못함 — 보냈는지는 화면이 모른다) = `.sd-callout--attention` 안에 첫 줄 `.sd-status--attention` · 설명 문장 · `.sd-actions` 의 [닫기](`.sd-btn--ghost.sd-btn--sm`). 자리는 본문 스크롤 영역의 흐름 안(관련 입력 바로 위)이고 고정 영역에 두지 않는다. 칸 아래 오류 자리(§6 「칸 오류 문구」)는 다음 제출·수정으로 풀리는 오류만 쓰고 이 확인 알림과 함께 쓰지 않는다. 수명은 원인에 묶는다(§16-10): 사용자가 닫거나 원인이 풀리면(예: 다시 첨부·보내기 성공) 사라지고, 닫기 전에는 다시 열어도 보인다. 닫기는 「확인했다」는 신호이지 결과(전송 성공 등)를 바꾸지 않는다. 설명 문장은 `role="status"` 로 두고, 상자를 보인 뒤 글을 넣어 낭독되게 한다(처음부터 들어 있는 글은 읽지 않는다). 관련 입력칸의 설명(`aria-describedby`)에도 잇는다. 닫거나 저절로 사라질 때 포커스가 그 안에 있으면 본문 영역으로 옮긴다.
- **파괴적 행동** — 실행 버튼은 언제나 잉크(solid). 라벨 = 동사 + 대상(+수량). 되돌릴 수 있으면 색 없음(v0.7.1 — 「색 없음」은 상태색을 쓰지 않는다는 뜻이며 실행 단추는 solid 다. 같은 자리에서 상태에 따라 바뀌어 나오는 반대 동작(예: [닫기]↔[되살리기])은 ghost. 성격이 다른 단추는 동사 라벨과 solid/ghost 로만 가르고, 색·테두리·새 변형으로 가르지 않는다). 되돌릴 수 없으면 확인 구획을 `.sd-callout--attention` 으로 열고 첫 줄에 「되돌릴 수 없습니다」(`.sd-status--attention`, v0.7.0 — `error` 는 이미 일어난 오류·실패에만 쓰고, 일어날 수 있는 위험은 `attention` 이다. KRDS 의 오류/경고 구분과 같다). 빨강 버튼 면은 쓰지 않는다.

### base.css
`color-scheme: light` 강제 · `[hidden]` 은 언제나 숨김(`.sd-*` 의 `display` 를 이긴다, v0.7.0) · `body` 글꼴 = `--font-sans` · `::selection` 브랜드 틴트 · `mark`(찾은 낱말 = 브랜드 틴트 · 지금 위치 `mark[aria-current="true"]` = 잉크 면 + 흰 글자, v0.8.1 — 아래 행동 패턴 「검색 강조」) · **폼 컨트롤 직각 강제**(브라우저 기본 라운딩 제거 — Safari search 입력 포함) · 네이티브 컨트롤 `accent-color: ink` · `.brand-ring`(포커스: surface 갭 → **ink 고대비 링**(주 표시) → `brand-hover` halo(보조), outline 은 투명으로 남겨 강제 색상 모드에서 보이게) · `.brand-underline`(텍스트 링크 표준: 글자색 = 둘레, 브랜드색 밑줄, 두께 `from-font`, offset 3px) · 위의 `sd-*` 클래스 전부. **레이어로 감싸지 않는다** — 가져오는 방법은 §17.

포커스 링을 내장한 것: `sd-btn`·`sd-field`·`sd-tab`·`sd-list-item`·`sd-details > summary`·`sd-block-link`·표 정렬 단추·`sd-table-wrap`(키보드 스크롤 상자)·`pre.sd-code`(넘치는 코드 블록)·텍스트 링크(`.brand-underline`·`.prose a`·`.sd-prose a`, v0.7.0)·건너뛰기 링크(`.sd-vh`)·`.sd-range` 손잡이·체크박스·라디오. `sd-composer` 바깥 묶음은 링을 받지 않는다(위 복합 입력, v0.6.1). 이들에는 `brand-ring` 을 따로 붙이지 않는다. 그 밖의 커스텀 인터랙티브 요소에는 `brand-ring` 을 쓴다.

**텍스트 링크 규칙**: 본문 속 링크는 `.brand-underline` 하나로 통일. `underline` 단독 사용 금지. 문장 밖에 홀로 선 링크는 `.sd-target` 을 함께 쓴다.

`@tailwindcss/typography` 플러그인을 쓰는 소비처 전용 토큰 글루(v0.2.0). `dist/prose.css`(버전 도장, v0.7.0)를 복사해 `tokens.css`·`base.css` 다음에 import. 일반 CSS·생성 HTML 은 이 파일 대신 `.sd-prose`.
- 플러그인의 gray 팔레트 변수(`--tw-prose-*`) 전체를 시맨틱 토큰으로 강제(body/headings=ink · counters/bullets/captions=ink-faint · hr·td 선=line · 표 머리선=ink(공통 표와 같음, v0.7.0) · pre 배경=surface-subtle).
- 제목 크기·굵기를 6단 스케일로 정렬(§4), 링크는 brand-underline과 동일 시각(포커스 링은 base.css 링 목록의 `.prose a` — v0.6.1), 코드 블록 라운딩 제거(직각), `kbd` 의 라운딩·그림자 제거(v0.7.0).

- `.prose` 안에 `sd-*` 부품을 두면 typography 규칙(utilities 층)이 부품을 이긴다 → 부품은 `not-prose` 로 감싼다(§17).

## 7. 차트·데이터 시각화

## 8. 모션

`transition-colors`(기본 150ms) **하나만**. 이동·확대·페이드 등 장식 애니메이션 금지. `duration-*` 클래스 직접 지정 금지. `transition-opacity` 등 다른 transition도 금지. 호버 피드백(v0.7.0 정리): 면이 있는 조작물·행 = `brand-hover` 틴트(회색 호버 금지 · 면 없는 아이콘 단추 plain 도 호버·누름 때 이 틴트를 면으로 보인다, v0.11.0) · 글자 조작물(텍스트 링크) = 호버 변화 없음(밑줄이 이미 조작 신호다).

공식 예외: 로딩 스켈레톤의 `animate-pulse` — 장식이 아니라 로딩 상태 피드백(그 외 keyframe 애니메이션 금지). 스켈레톤 막대 폭은 고정값으로 둔다. 모션 줄이기 설정(`prefers-reduced-motion: reduce`)에서는 스켈레톤이 멈춘다. 1초 안에 끝나는 로딩에는 스켈레톤·진행 문구를 보이지 않는다(v0.7.0 — 깜빡임만 남는다).

진행 표시에 새 움직임을 들이지 않는다: 「{동사} 중…」 문구로 쓰고 평소 소요를 넘기면 경과 시간을 덧붙이며(v0.7.4 — §16-9), 깜빡이는 점·스피너를 새로 만들지 않는다(v0.6.0 · §6 행동 패턴).

## 9. 접근성 기준

- 텍스트 대비 ≥4.5:1 (토큰이 보장 — `ink-faint`가 하한), 그래픽 ≥3:1.
- 모든 인터랙티브 요소에 포커스 링(예외 = 복합 입력의 바깥 묶음, 아래 "복합 컨트롤 포커스") — 조작 클래스(§6 base.css 목록)는 내장, 보조 클래스(`sd-target` 등)와 그 밖의 커스텀 요소는 `brand-ring` 의무. 포커스 주 표시는 ink 고대비 링(≥3:1), **brand 단독 포커스 링 금지**(대비 1.36:1 미달).
- 터치/클릭 타깃: 버튼 md 40px 기준(sm은 보조 액션과, sm 자리에서 시작한 확인 단추에 한정, v0.10.1). 문장 밖에 홀로 서는 텍스트 링크(BackLink·목록형 링크 등)는 크기 ≥24×24px 확보(WCAG 2.2 2.5.8 AA) — BackLink는 `.sd-target` 내장(§6), 커스텀 단독 링크도 `.sd-target` 으로 양축을 보장한다. 본문 문장 속 링크는 인라인 예외 — 줄 높이에 종속되므로 24px을 강제하지 않는다.
- 색 단독 정보 전달 금지(§1-4). 상태 변형(`--error`·`--attention`)은 언제나 문구를 함께 쓴다 — 인셋 안내는 첫 줄에 같은 뜻의 `.sd-status` 문구를 둔다.
- **강제 색상(고대비) 모드**(v0.6.0): 이 모드는 `box-shadow` 와 그라데이션 배경을 지우고 면을 시스템 색으로 바꾸지만 `border`·`outline` 은 시스템 색으로 그린다. 그래서 ① 포커스는 `outline` 을 지우지 않고 투명으로 둔다(이 모드에서 보인다 — 복합 입력의 textarea 도 같다, v0.7.0) ② 버튼은 투명 1px 테두리를 갖는다 ③ 상태 표지는 `border` 로 그린다 ④ 셀렉트는 이 모드에서 네이티브 화살표로 돌아간다. 목록 행·탭의 선택선은 투명 테두리를 쓰지 않는다(이 모드에서 모든 행에 선이 생긴다) — 선택된 것만 테두리를 갖고 나머지는 padding 으로 자리를 맞춘다. 값 선택 펼침 목록의 체크(v0.8.0)도 테두리로 그려 이 모드에서 남는다.
- 복합 컨트롤 포커스: 안쪽 조작 요소(`:focus-visible`)가 각자 링을 갖는다. **예외 — 복합 입력(`.sd-composer`)의 바깥 묶음에는 링이 없다**(v0.6.1): 글자 커서가 보이는 textarea 는 WCAG 2.4.7(AA)을 충족한다(W3C Understanding 2.4.7 의 예 "a vertical bar is displayed in the field"). 2.4.13(AAA 포커스 모양)은 충족하지 않음을 알고 받아들인다. 마우스 클릭에도 textarea 는 `:focus-visible` 이 되므로 "키보드일 때만 링"은 스크립트 없이 만들 수 없어 쓰지 않는다.
- 아이콘 전용 버튼은 `aria-label` 필수. 뜻을 `title` 툴팁에만 두지 않는다 — 아이폰에서는 `title` 이 보이지 않는다(v0.7.0).
- 비활성(`disabled`·`aria-disabled="true"`) 컨트롤은 대비 기준의 예외다(WCAG 1.4.3 — 비활성 요소는 대상 밖). 그래서 비활성은 "지금 쓸 수 없음"만 뜻하고, 정보를 비활성 모양에 담지 않는다.
- 호버는 포인터가 있는 기기에서만 건다(`@media (hover: hover)`, v0.7.0). 입력칸 글자는 16px(§4).
- 고정 요소(머리글·표 고정 머리·고정 입력창 등 하단 요소) 아래로 포커스가 가려지지 않게 스크롤 상자에 `scroll-padding-top`·`scroll-padding-bottom`(고정 요소 높이)을 준다. 높이는 테두리·안쪽 여백·safe-area 를 포함한 바깥 크기(border-box)로 잰다(v0.8.1). 스크롤 상자 안 조작 목록은 위아래 8px 여백을 둬 포커스 링이 잘리지 않게 한다(v0.7.0).
- 320px 폭에서 표·코드 블록 말고는 가로 스크롤이 생기지 않는다. 글자를 200% 확대해도 고정 입력창과 전송 단추가 가려지지 않는다(v0.7.0).
- 포커스 이동과 복귀: 오류 요약이 나타나면 그 제목으로 포커스를 옮긴다(칸이 하나뿐인 입력은 포커스를 옮기지 않는다 — §6 「칸 오류 문구」, v0.11.0). 제자리 확인 구획의 포커스 대상과 복귀는 §6 「제자리 확인」을 따른다(v0.7.2).
- 넓은 표의 스크롤 상자(`.sd-table-wrap`)와 코드 블록(`pre.sd-code`, v0.6.1)은 키보드로 스크롤할 수 있게 `tabindex="0"` + `role="region"` + `aria-label` 을 준다.

## 10. 브랜드 위계

- **sidoyu** = 메인 브랜드(사이트 전체). 로고타입은 `font-bold` 텍스트 "sidoyu".
- **YUNSFEED** = 뉴스레터 서브브랜드. 뉴스레터 영역 명칭에만 사용하고 **토큰은 전부 공유**(별도 색·폰트 없음).

## 11. 새 프로젝트 적용 절차 (5단계)

1. `dist/tokens.css` + `dist/base.css`를 프로젝트에 복사(또는 raw URL — **버전 태그 고정**, `main` 추적 금지). globals.css 순서: `@import "tailwindcss";` → `@import "./design/tokens.css";` → **`@import "./design/base.css" layer(components);`** → (선택) prose.css. `@tailwindcss/typography`를 쓰면 `dist/prose.css`도 함께(§6). 일반 CSS 소비처는 §17.
2. Geist 폰트 연결: next/font로 Geist·Geist_Mono 로딩 후 `@theme { --font-sans: var(--font-geist-sans), "Apple SD Gothic Neo", "Noto Sans KR", ui-sans-serif, system-ui, sans-serif; --font-mono: var(--font-geist-mono), ui-monospace, "SF Mono", Menlo, monospace; }` glue 추가. tokens.css 가 같은 이름의 전체 스택을 이미 내보내므로, glue 는 첫 글꼴만 바꾸고 한글 폴백을 지우지 않는다(v0.7.0). next/font 의 `variable` 클래스는 `<html>` 에 붙인다 — `@theme` 변수는 뿌리 요소에서 풀리므로 `<body>` 에만 붙이면 `--font-geist-sans` 를 찾지 못해 시스템 글꼴로 내려간다(또는 glue 를 `@theme inline` 으로 쓴다).
3. 필요한 프리미티브(`*.tsx`)와 `cx.ts`를 `registry/ui/`에서 `components/ui/`로 복사(차트 쓰면 `chart-palette.ts`도 `lib/design/`에).
4. `dist/design-check.sh`(버전 도장, v0.7.0)를 `scripts/` 에 복사 + package.json에 `"design:check": "bash scripts/design-check.sh"` 추가. 의도적 예외는 `.design-check.allow`에 사유 주석과 함께.
5. 첫 페이지를 PageShell로 작성하고 `npm run design:check` 통과 확인.

> 비 Tailwind 환경은 두 갈래다(§17): 일반 CSS·생성 HTML 은 `dist/tokens.vars.css` + `dist/base.css` 를 그대로 쓴다(값을 손으로 옮기지 않는다). CSS 를 쓸 수 없는 메일·확장 팝업만 `dist/tokens.flat.json` 값을 쓴다.

## 12. 금지 패턴

> `design-check.sh`는 아래 중 정규식으로 잡히는 것만 검사하는 **보조 안전망(부분 검사)**이다. 권위는 이 문서 전체. "검사" 열: ○ = 검사가 잡는다 · × = 사람이 지킨다. 검사는 클래스 문자열(따옴표·백틱·공백·변형 접두 `sm:`·`hover:` 뒤)과 CSS 선언을 보고, 첫 줄에 AUTO-GENERATED 도장이 있는 사본은 건너뛴다(v0.7.0). 서버 코드(`.py` 등)가 만드는 HTML 은 검사 밖이다 — 대신 §17 "dist 를 읽어 끼운다" + 이관 때 렌더 확인.

| 패턴 | 대신 | 검사 |
|---|---|---|
| `dark:*` · `prefers-color-scheme: dark` | 없음 — 라이트 전용 | ○ |
| class 안 인라인 hex | 색 토큰 | ○ |
| `text/border/bg-black/N`, `white/N` | `ink-muted` `ink-faint` `line` `surface-subtle` | ○ |
| 토큰 투명도(`bg-ink/N`·`text-ink/40` 등) | 정해진 토큰 값 · solid 호버는 `.sd-btn` 내부 구현 | ○ |
| `rounded*` 전부·0 이 아닌 `border-radius` | 없음 — 직각 모서리(§1-3-1) | ○ |
| `shadow-*`·`backdrop-*`·`box-shadow` | 없음 — 플랫(포커스 링은 base.css 정본만) | ○ |
| `linear/radial/conic-gradient(` | 없음 — 플랫(셀렉트 화살표 도형은 base.css 정본만) | ○ |
| `border border-line` 사면 박스(순서 무관) | 구획은 수평선·여백(§1-3-2). 기능 테두리 세 가지만 예외(`.design-check.allow`에 사유) | ○ |
| `max-w-md/3xl/5xl` 등 | PageShell(`max-w-wide/reading/narrow`) | ○ |
| `text-xl`·`text-4xl` 이상 | 스케일 6단 안에서 해결 | ○ |
| 400·500·600·700 밖의 굵기 | §4 굵기 넷 | × |
| `leading-*` | `text-*` 가 주는 줄간격 · 긴 글은 `.prose`/`.sd-prose` | × |
| 단독 `underline` | `.brand-underline` | ○ |
| `duration-N` 직접 지정 | `transition-colors`(기본 150ms) | ○ |
| `transition`·`transition-all/opacity/transform`·`animate-spin/bounce/ping` | `transition-colors` 하나(스켈레톤 `animate-pulse` 만 예외) | ○ |
| `text-brand` · `bg-brand`(면) | brand는 정체성 포인트(§1-2) | ○ |
| `border-brand`·`outline-brand`·`ring-brand`·`decoration-brand` | 선택 = 잉크 · 포커스 = 내장 링 또는 `brand-ring` · 링크 = `brand-underline` | ○ |
| `bg-error`·`bg-attention`(상태색 면) | 상태색은 글자·선·표지에만 — `.sd-status`·`.sd-callout` | ○ |
| 상태 이름에 색 이름(「노랑」·「초록」) | 의미어(「점검 필요」·「실패」·「정상」 — §16) | × |
| 토스트 | 제자리 문구·인셋 안내(§13) | × |
| 내용보다 작게 눌리는 복합 입력 테두리 상자(안의 도구줄이 테두리 밖으로 넘침) | 상자 안 스크롤 칸(입력칸·첨부 목록)만 줄인다(§6 복합 입력 · §5-1) | × |
| 확인 알림(사용자가 확인하면 목적이 끝나는 알림)을 닫을 수단 없이 고정 영역(입력칸 아래 등)에 오래 두기 · 알림을 정한 시간 뒤 저절로 지우기 | 닫을 수 있는 확인 알림(§6 행동 패턴 · §16-10) | × |
| `summary` 에 `aria-label` | 머리줄 문구 자체가 이름(§6 접이식) | × |
| 뜻을 `title` 툴팁에만 | 보이는 문구·`aria-label`(§9) | × |
| 임의값: `text-[..]` `p*/m*-[..]` `gap-[..]` | 스케일 6단·4px 간격 스케일 (차트 내부 값은 chart-palette 상수) | ○ |
| Tailwind 팔레트 색 (`red-600` `gray-500` 등) | 시맨틱 토큰 — 상태색 = `error`·`attention` 토큰만(팔레트 허용이 아니다) · 차트 데이터 색은 chart-palette | ○ |
| 부품을 손으로 다시 그리기 — React 부품(카드·버튼·입력 등)이든 §6 CSS 규격(코드 블록·표·접이식·인셋 안내 등)이든, 인라인·별도 CSS 모두 | 그 부품을 쓰고 소비처는 배치만(§6 경계 규칙) | × |

- 토큰·컴포넌트를 바꾸면: ① tokens.json/소스 수정 ② `npm run build`(dist/ 재생성 — `base.css`·`prose.css`·`design-check.sh` 에 버전 도장 + `registry/ui/*.tsx` 첫 줄 버전 도장 갱신. 버전은 `tokens.json` 의 `meta.version` 한 곳에만 적는다 — package.json·이 문서에 판 번호를 적지 않는다) ③ CHANGELOG 기록 ④ 소비 프로젝트는 각자 버전업 시점에 마이그레이션 메모를 보고 갱신.
- 판 올림: 클래스·토큰·부품을 더하면 minor, 값·문서·버그 수정만이면 patch(CHANGELOG 머리 규칙).
- 새 토큰/variant 추가 전 자문: "기존 토큰·크기·위계로 해결되지 않는가?" — 대부분 해결된다.

## 16. 상태 표기와 문구 (v0.6.0)

1. **상태 네 축**: 정보 상태(정상·주의·문제) / 진행 / 업무 상태(활성·유휴 = 잉크 농담) / 조작 상태(선택·포커스·비활성). 상태색은 주의·문제에만 쓴다.
2. 상태 이름은 의미어로 쓴다(「점검 필요」·「실패」 — 「노랑」·「초록」 금지).
3. **판정 불가는 정상보다 조용하게 보이지 않는다** → `attention`(sidoyu 자체 결정).
4. 공통 부품은 상태를 추론하지 않는다. 예: 「접수됨 · 배달 미확인」은 완료가 아니다.
5. 한 화면의 정보 상태는 3개(정상·주의·문제)로 시작한다 — sidoyu 자체 결정이며, 외부 근거는 "표시기가 5~6개를 넘으면 인지 부담"이라는 IBM Carbon 지침이다(엄격한 상한이 아니다). 여러 상태를 묶어 요약하면 가장 심한 것으로 대표한다.
6. 문구 틀: 진행 「{동사} 중…」(평소 소요를 넘기면 + 경과) · 완료 「{대상} {과거형}」 · 오류 「무엇이 · 왜(알면) · 다음 행동」 · 빈 화면 「없는 것 + 다음 행동 하나」 · 버튼 = 동사 + 대상 · 파괴적 행동 = 예약어 + 대상.
   - **문장 어미 = 합니다체**(v0.7.0, 2026-10-29 소유자 결정): 「닫았습니다」·「시작했습니다」·「확인할 것이 있습니다」. 한 화면 안에서 해요체(「시작했어요」)를 섞지 않는다. 버튼·라벨·진행 문구처럼 문장이 아닌 문구는 어미가 없다(「대화 닫기」·「올리는 중…」).
   - **요청 문구 = 합니다체 알림문**(v0.7.1, 2026-10-29 소유자 결정): 사용자에게 할 일을 알릴 때 「~해 주세요」로 부탁하지 않고 가능·조건·필요한 행동을 알리는 문장으로 쓴다(「다시 시도할 수 있습니다」·「보내려면 연결이 필요합니다」). 입력칸 안내와 「할 일:」 뒤는 명사형(「이 대화에 보낼 메시지…」).
7. 사용자가 직접 한 행동의 결과는 그 자리에서 보여 준다(토스트 아님).
8. **대화 화면의 역할 구분**(v0.7.0 개정, 2026-10-29 소유자 결정): 사용자 발화 = 오른쪽 + `surface-subtle` 면(`.sd-user-turn`, 직각·테두리 없음) · 답 = 왼쪽 기준선, 면·라벨 없음. 보이는 「나」 라벨은 두지 않고, 발화마다 화면낭독기용 `<span class="sd-vh">나:</span>` 를 둔다. brand·상태색으로 역할을 가르지 않는다. 이유: Claude·ChatGPT 앱과 같은 관례라 따로 배우지 않아도 "오른쪽 면 = 내 글"로 읽힌다(사용자 친화성). 면은 위치와 함께 역할을 알리므로 §1-4(색 단독 금지)를 지킨다.
9. **요청 중 단추**(v0.7.4, 2026-11-02 소유자 결정 — v0.7.0 의 「라벨 유지 + 옆 진행 문구 · 버튼 모양 그대로」를 번복): 누른 단추 자리의 글자가 상태를 말한다.
   - 요청을 보내는 단추는 글자 단추로 둔다(아이콘 단추는 진행 중에 글자로 바꿀 자리가 없다).
   - 누르면 그 단추 글자가 「{동사} 중…」(예: 「닫는 중…」·「시작하는 중…」)으로 바뀌고 `aria-disabled="true"` 로 흐려진다. 네이티브 `disabled` 는 포커스를 잃게 하므로 쓰지 않는다. 재제출 차단은 스크립트가 맡고, 가드는 전송 함수의 맨 앞(입력 검사보다 앞)에 둔다. 끝나면 원래 글자로 돌아가고 결과는 상태 문구가 알린다(#7).
   - 보이는 글자가 이름이 되도록 고정 `aria-label` 을 두지 않는다(WCAG 2.5.3). 시작·완료·실패 낭독은 `role="status"` 문구가 맡는다(§9 진행 표시).
   - 1초 안에 다른 단추로 바뀌는 단추(보내기 → 중지)는 글자를 바꾸지 않고 흐리게만 한다(§8 — 1초 안에 끝나는 로딩에는 진행 문구를 보이지 않는다).
   - 경과 시간은 단추 글자에 넣지 않는다(폭이 매초 흔들린다). 단추 밖·낭독 영역 밖에 두고, 평소 소요를 넘긴 뒤에만 보인다. 응답이 끝내 오지 않으면 정한 상한에서 「확인 필요」 안내로 넘긴다.
   - 제출 버튼은 미리 비활성하지 않는다 · 제출 시 오류가 하나 이상이면 오류 요약으로 포커스를 옮긴다(칸이 하나뿐인 입력은 예외 — §6 「칸 오류 문구」, v0.11.0)(Vercel Web Interface Guidelines 의 사전 비활성 금지 + GOV.UK Design System 의 오류 요약 포커스 — 진행 중 글자 교체는 sidoyu 자체 결정이다).

10. **알림의 수명**(v0.11.1): 알림은 원인에 묶어 사라진다 — 제출 오류는 다음 제출·수정까지 · 진행은 끝날 때까지 · 사용자 행동의 결과 문구는 다음 행동까지 · 확인이 필요한 알림은 사용자가 닫거나 원인이 풀릴 때까지. 시간이 지났다는 이유로 지우지 않는다(#3 — 판정 불가는 조용해지지 않는다). 닫기 수단은 사용자의 확인으로 표시 목적이 끝나는 확인 알림에만 둔다 — 현재 상태·진행·아직 풀리지 않은 입력 오류는 그 상태가 풀릴 때까지 보이고 닫기를 붙이지 않는다. 알림을 닫았다는 사실은 결과가 정상이라는 뜻이 아니다(#4).

> 출처: 오류 요약·칸 오류·접이식·인셋·면 없는 표 헤더 문법은 [GOV.UK Design System](https://design-system.service.gov.uk/) 을 각색했다(문서 = [Open Government Licence v3.0](https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/), 별도 표시된 부분 제외). 상태 표시기 수에 관한 지침은 IBM Carbon Design System, `attention` 이라는 이름은 GitHub Primer 에서 참고했다. 문장은 sidoyu 가 다시 썼다.

## 17. 환경별 전달 (v0.6.0)

| 소비처 | 가져가는 것 | 순서·방법 |
|---|---|---|
| Tailwind | `dist/tokens.css` · `dist/base.css` · (선택) `dist/prose.css` · `registry/ui/*.tsx` + `registry/ui/cx.ts` · `dist/design-check.sh` | `@import "tailwindcss";` → `@import "./design/tokens.css";` → `@import "./design/base.css" layer(components);` → prose.css. 레이어로 넣어야 className 유틸리티가 `sd-*` 위에 온다 |
| 일반 CSS | `dist/tokens.vars.css` · `dist/base.css` · `dist/design-check.sh` | `<link>` 순서 tokens.vars → base → 소비처 CSS. base.css 는 레이어 밖이라 보통의 선택자 우선순위로 동작하고, 소비처의 `*`·요소 선택자 초기화는 `.sd-*` 에 진다. 우선순위가 같거나 높은 소비처 규칙은 여전히 이기므로 아래 경계 규칙을 지킨다 |
| 생성 HTML(서버가 HTML 문자열을 만드는 경우) | 같음 | 생성 시점에 `dist/` 파일을 읽어 `<style>` 에 끼운다(내보낸 HTML 이 자립형으로 남는다). 생성 코드 안에 CSS 를 붙여 넣지 않는다(손 복사가 다시 생긴다) |
| 메일·확장 팝업 | `dist/tokens.flat.json` 값 | CSS 변수를 쓸 수 없는 곳만 값을 인라인으로 쓴다 |

- **CSS·토큰·검사 스크립트는 `dist/` 파일만 복사한다**(`registry/ui/` 에서 가져가는 것은 React 부품 `*.tsx` + `cx.ts` 뿐이다, v0.7.0). 복사한 파일들과 tsx 첫 줄의 버전 도장이 같은지 확인한다 — 토큰 파일과 base.css 의 판이 다르면 새 토큰(예: `--color-error`)이 정의되지 않아 색이 소리 없이 사라진다.
- **태그 고정**(`main` 추적 금지). 자동 갱신은 없다 — 소비처가 각자 버전을 올린다.
- **웹폰트 파일은 소비처가 불러온다**(v0.7.0): 토큰은 글꼴 이름(`--font-sans`·`--font-mono`)만 정한다. 일반 CSS 소비처는 `@font-face` 로 `"Geist"`·`"Geist Mono"` 를 그 이름 그대로 등록한다. 불러오지 않으면 한글 폴백·시스템 글꼴로 내려간다. 일반 CSS·생성 HTML 소비처의 `@font-face` 는 `font-display: optional` 로 두고(늦게 도착한 글꼴로 화면이 다시 짜이지 않는다), 글꼴 파일 주소에 내용 지문(해시)을 넣어 오래 보관(장기 캐시)하게 한다(v0.8.1).
- **검사**: 일반 CSS 소비처는 design-check 에 실제 소스 경로를 넘긴다(예: `bash design-check.sh static`). 서버 코드가 만드는 HTML 은 검사 밖이므로 이관 때 렌더 확인으로 대신한다.
- **경계 규칙**(정본 = §6 머리): 소비처 CSS 는 부품 요소에 배치 선언만 둔다. 옮겨 올 때 base.css 가 대신하게 된 소비처의 시각 선언과 옛 전역 규칙(전역 `:focus-visible` 링 등)을 지운다.
- `.prose` 안의 `sd-*` 부품은 `not-prose` 로 감싼다.
- 복구 단위 = 소비처마다 "토큰·CSS·React·마크업·스크립트를 함께 바꾼 마이그레이션 변경 전체"를 되돌리는 커밋이다. 라이브러리 파일만 되돌리면 새 마크업의 스타일이 사라진다.
